# Problem 

Detect fraudulent transactions in a high volume payment stream with extreme class imbalance (~3.5% fraud), evolving fraud tactics (concept drift), and strong network effects (shared devices, IPs, cards…).

## Key Challenges
- Extreme class imbalance
- Concept drift / novel fraud patterns
- Need for real-time (or near real-time) scoring
- Regulatory pressure → must provide explanations
 Limited investigator time → high precision at top-k is critical


 ## Goals for me : 

 - Master time aware validation and drift detection
 - Build a full unsupervised -> supervised pipeline 
 - Design a realistic human-in-the-loop system
 - Undertand which features are stable vs brittle
